# Video Game Asset Creator: architecture (quick guide)

**Maintenance rule.** Any change to how the app is built (a new module or step, the job queue or card routing, the data model, the order of clean-up's passes, where files live, how the parts start) updates the affected lines of this file in the same piece of work. Keep entries to a few lines. No history, no plans: only what exists.

A local Windows app that turns one picture into a rigged, game-ready 3D model in six steps. Nothing is uploaded; no model is bundled. Not repeated here: [README.md](README.md) (install and use), [docs/FIRST-TIME-SETUP.md](docs/FIRST-TIME-SETUP.md), [docs/ADVANCED.md](docs/ADVANCED.md) (settings, running from source), [docs/API.md](docs/API.md), [docs/BACKEND.md](docs/BACKEND.md) (module map, adding an engine), [docs/BUILD-THE-EXE.md](docs/BUILD-THE-EXE.md).

| Part | Where | Notes |

Preferences set in the app: `library/prefs.json` (`prefs.py`).

## 2. Data model (`db.py`, `library.py`)

- **Project**: name, platform, `style_lock` (the look), optional `unity_project_path`.
- **Asset**: category, look (`style_preset`), platform, prompt; `base_asset_id` (variant), `autopilot` state, `held_item`/`equipment` (items), `hair` (library choice), `face_matters`, `wears_armour`/`body_is_metal` (the two step 1 tick boxes; NULL = read the description, a tick wins; the clean-up reads them).
- **Version**: one result of one step: `stage`, `parent_version_id`, `status` (`queued`, `running`, `done`, `error`, `rejected`; "stopped" = rejected with error `cancelled`), `params`, `files` (key to library-relative path), `metrics` (including `checks`), `selected` (kept; one per asset and stage).
- **Job**: the queue row: `instance` (`a`, `b`, `host`), `kind` (`<stage>.<op>` or `material.<stage>.<op>`; ops `run refine adjust upload upscale compose judge`), `status`, `progress`, `message`, `payload`.
- A run's parent is the kept version of the previous step (`pipeline.run_stage`; the material category skips step 2). A **redo** is a sibling with the same parent. **Refine** (a change in words) and **adjust** (settings) make a child version of the same step with the parent's params as the start. Nothing is overwritten. Steps find inputs by walking up the parents, then the kept version of each step (`StageContext.lineage_file`).
- Files: `library/projects/<project>/assets/<asset>/<stage>/<version>/`, served by `GET /api/library/{path}`. Exports are also copied to `exports/<project>/<asset>/` beside `library/`, which also holds `vgac.sqlite`, `prefs.json`, `engines.json` and the registries of the person's own parts.
- Schema changes: add a nullable column to `_ADDED_COLUMNS` in `db.py`; there is no other migration.

## 3. The six steps

Each is `backend/vgac/stages/<stage>.py` with `run`, `refine`, `adjust`, `judge`; `stages/base.py` gives it a `StageContext`. Settings: `reference.STAGE_SCHEMAS`. Checks go in `metrics.checks`.

| Step (stage id) | In | Out | Work | Main modules |
|---|---|---|---|---|
| 1 Describe (`concept`) | description, or the person's own picture(s) | picture and cut-out | card B: one of six painters by look, BiRefNet cut-out; refine = Qwen-Image-Edit | `stages/concept.py`, `own_images.py`, `compose.py`, `readiness.py`, `buildpose.py` |
| 2 Check all sides (`turnaround`) | kept picture | front, left, back, right, three-quarter views (two for humanoids) with cut-outs; bald copy for library hair | card B: Qwen-Image-Edit with a LoRA by `turn_method`; can borrow the other card to draw both sides at once; per-view checks incl. `same_side`, `pose_held`; redraws a failing view up to twice; pose check for the 3D build (`pose_for_3d`) and an optional guarded pose redraw (`pose_ready`: wide A pose, `buildpose.guard`, one retry, else the person's picture) | `stages/turnaround.py`, `baldpic.py` |
| 3 Build the 3D model (`mesh`) | kept views | `glb`, texture maps | card A: TRELLIS.2 (or Hunyuan3D-2mv); normal fix, colour match, rebuild when too dark; optional head built on its own; silhouette audit in Blender; or the person's own model | `stages/mesh.py`, `graphs/trellis.py`, `headgraft.py`, `texcolour.py`, `colourmatch.py`, `normalfix.py`, `model_import.py` |
| 4 Clean up (`prep`) | kept 3D model | `prep.glb`, final maps, report | host (Blender) plus CPU and an image card for the face pass | `stages/prep.py` and the list below |
| 5 Make it move (`rig`) | clean-up model | rigged `glb`, `anim_glb`, hit boxes | card B: SkinToken by category `rig_engine` (`none` = rigid, passes through); then Blender: bend renders, hit boxes (`blender/hitboxes.py`; on humanoids the forearm capsule runs on over the hand and each shin region has a second capsule along the foot, `Hit_Foot_L` and `Hit_Foot_R`, ignoring stray foot-owned skin beyond 0.6 foot lengths: 13 shapes), moves, spring bones, hair bind; missing finger chains are built from the hand's shape after `rig_fix` and before anything reads the skeleton (`_fingers`, `blender/finger_build.py`; never on a hand the skeleton saw as one chain or none; setting `build_fingers`); the four fingers are named by lane from the thumb in each hand's own frame (`rig_fix.finger_lane_order`: position across the hand from the thumb base, square to the wrist-to-fingertip direction, so it does not depend on the body's front; Left and Right of limbs still come from the toe-derived front); then the fingers are made rigid (`_finger_rigid`, `blender/finger_rigid.py`: each chain straight with joints at 0.45 and 0.75 of the finger, thumb 0.40 and 0.73; each segment's skin on its own bone with a 6 mm blend at each joint; the first bone stops at the knuckle; skin moves only between a finger's own bones and the palm bone; setting `finger_rigid`, default on; `finger_build` accepts fingertip marks with `--marks`, off until the Check the joints screen exists); then the hands are turned palm-down (`_palm_down`, `blender/palm_down.py`: step 1 draws open palms forward, so the rig is fitted palm-forward and neither the retarget T-pose nor Unity's `EnforceTPose` fixes roll; Hand is rolled about the arm axis, three `Extra_ForeArmTwist` bones in a chain between ForeArm and Hand keep the forearm's thickness, the posed mesh is baked in as the rest pose, `metrics.palm_down` records the degrees per hand; setting `palm_down`); the retarget limits each finger joint's turn (`blender/retarget.py --finger-cap`, `gait.cap_turn`; setting `finger_cap`, default 40 degrees, 0 off; clips that need a fist or a grip are exempt; Unity's shared Humanoid clips keep the library's curl); checks `fingers` (per hand: complete, built, or lump; also requires the fingers in lane order from the thumb and every chain on the hand's skin: `rig_info.py` writes `finger_chains`, the worst joint distance from skin per finger, limit 3 cm) and `limb_joins` (cuts across each limb on the rig model) | `stages/rig.py`, `limbjoins.py`, `moves.py`, `springs.py`, `blender/` |
| 6 Hand off (`export`) | rig (or clean-up) model | FBX, GLBs (LODs, Godot), texture packs, `sockets.json`, `manifest.json`, optional sprites, Unity report | host: collision shapes, Blender pack, Unity import, delivery | `stages/export.py`, `colliders.py`, `sockets.py`, `blender/pack.py` |

The **material** category (tileable surface) uses `stages/material.py` for steps 1, 3 and 6 on card B and skips 2, 4 and 5.

**Clean-up order** (`stages/prep.py` `_prep`):
1. facing decision, outline test then a toes test as tie-break (`facing.py`)
2. normal-map repair for old 3D versions (`normalfix.py`)
3. Blender `prep.py`: turn, size, pivot, weld, weighted decimation to the budget, shading, optional symmetrize, grid snap for scenery, rebake
4. texture pass: measure, physically based fix, look applied; light removed here only when no picture will be painted
5. picture projection into the base colour (`srcproject.py`). The head is painted first by a chain of head views: the front picture fitted on the head by eyes and mouth (`facemarks.use_local`, MediaPipe on the processor), then each three-quarter view fitted the same way and lined up to what the front painted (refused when over 0.12 of the face width away); each three-quarter head picture takes the front's skin tone by one offset measured where the two overlap. Whole-body fits do not paint where a head view paints; they hand over gradually down about 6 cm of neck, their tone matched to the head views' in that band. A head view never paints its frame margin or surface seen beyond about 70 degrees; the chin underside takes the painted colour around it. Left, right and back views never paint the face; a view whose turn contradicts the front is refused. Unpainted skin inside the eyes-nose-mouth box takes the painted skin tone.
6. skin never metal (`skinmetal.py`): head, neck and the rest of the bare skin; armour in the description limits it to head and neck
7. hair found (`stages/hair_detail.py`); a grey metal crown is a helmet only when light enough to be steel and the face skin was not marked metal
8. face detail: close-up, fit, paint; held back when the fit scores under 0.65 (`stages/face_detail.py`, `face.py`, `facecloseup.py`, `facemarks.py`); skin never metal runs again when it laid the texture out anew
9. hair detail painted, optional own hair material (`hair.py`, `hairmat.py`)
10. light removed after painting (`lightfix.py`): Realistic look with pictures painted, only where same-coloured texels show a light gradient, at most one stop; `base_color_lit.png` keeps the original
11. physically based figures measured again on the finished maps
12. library hairstyle fitted to the body (`hairfit.attach`)
13. checks computed, incl. `picture_projection`, `skin_not_metal`, `facing_tests`, `face_finder`, `baked_light`; a texture check that cannot be measured says so (`quality.not_measured`)

Face and hair passes skip (reason recorded) for non-humanoids, crisp or flat looks, when off, or when nothing is found.

## 4. Job queue (`jobs.py`)

- One asyncio worker per ComfyUI instance in `config.yaml` plus one for the host; one job at a time each. Every worker waits while free RAM is under `min_free_ram_gb`.
- **Routing** (`route()`): the person's default card if it can run the work; else the step's card from `stage_instances` (`material_stage_instances`, `judge_instance`); else the first card that is on, allowed that kind (`allowed_kinds`) and capable (`instance_capabilities`; rigging is `b` only); else the job waits with a message. Host steps always run on the host.
- **Card off**: queued jobs move, the running job is stopped and requeued, never cancelled.
- **Share when busy**: an idle card takes the oldest waiting job from a busy card; a job is never split and a running job never moves.
- **Borrowing**: a running step may `lend` another card for part of its work (step 2; the host's clean-up for its face close-up, naming the work `kind` and the card to `avoid`). Lent only if on, allowed, idle, nothing waiting, engine already answering, enough free memory (`LEND_MIN_ROOM_GB`); the host borrows nothing while a step 2 job waits. Handed back at end, failure or stop; turning it off revokes it. An idle engine short of memory is told to let go of its models and is measured again. The face pass holds the card of its first close-up as a lease.
- **Engine address**: an engine's port is never looked up again while it has a job (`instances.py`, `comfy.py`).
- **Host lanes**: clean-ups run on the host's main worker, first come first served; exports run on a second worker (`HOST_QUICK`), so they do not wait behind another asset's clean-up, and one asset never has two host jobs at once. `host_cleanup_workers` (default 1) raises the number of clean-up workers.
- **Estimates with a second card**: the queue records on the borrowing job how long it had a lent card (`Job.result.lent`); `estimates.split_estimates` keeps runs with and without one apart, and `/api/stages` gives `estimate_two_cards`, `estimate_one_card` and `estimate_note`.
- **Rig first**: a card's queue starts a queued rig job ahead of other assets' long jobs (`jobs._card_pick`), never ahead of its own asset's unfinished earlier jobs, at most two rigs ahead of one waiting job.
- **Keep models loaded**: `instances.cache_ram_args` adds `--cache-ram <active> <inactive>` to engines the app starts when the card's `keep_models_loaded` pref is on (default on); inactive is 15 percent of the PC's RAM, between 6 GB and the free-RAM floor. ComfyUI otherwise drops cached models after any graph that does not use them. A job held for free RAM makes idle engines give their cached models back (`JobQueue.release_cached_ram`). The lending guard does not depend on it.
- **Estimates**: the upper-quarter mark of recent runs; a clean-up's progress follows the clock and the time left only falls; `note_waits` writes what a queued job waits for.
- **Stop** kills the task and child processes and interrupts ComfyUI; the version becomes "stopped"; **Resume** requeues with the same settings and seeds. **Timeout** (`job_timeout_seconds` 3600, `blender_timeout_seconds` 1800) is an ordinary failure. **Engine lost** mid-job: requeued once, then fails. **Backend restart**: running jobs return to queued.
- Websocket events: `job`, `version`, `gpus`, `autopilot` (`events.py`).

## 7. Conventions

- Anything the person reads is plain language, no stage ids or model file names as labels, no emoji. Wording lives in `guidance.py` (`tests/test_ui_plain_names.py` and `tests/test_option_help.py` enforce it).
- One source per fact (the table in section 5); do not copy it.
- A pass that is skipped records its reason in metrics and says it in plain words; it does not fail the step.
- Code with tests but not yet seen on a graphics card is marked `UNTESTED ON A CARD` in the comment and commit message, with a per-version switch (see `stages/turnaround.py`).
- Tests: from `backend/`, `.venv\Scripts\python -m pytest -q tests` (temporary library, no ComfyUI needed; a few need Blender, found by `tests/machine_tools.py`). Launcher: `node desktop/appbridge.test.js`, `node desktop/machine.test.js`. Frontend: `npm run build`, `npm run lint`.
- Loading a change: frontend, `npm run build` in `frontend/` and reload; backend, restart the process (reopening the app does not restart a backend the launcher did not start; check the queue is empty first); launcher, `npm run dist` in `desktop/` with all VGAC processes closed. Ship frontend and backend together.
