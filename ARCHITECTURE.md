# Video Game Asset Creator: architecture (quick guide)

**Maintenance rule.** Any change to how the app is built (a new module or step, the job queue or card routing, the data model, the order of clean-up's passes, where files live, how the parts start) updates the affected lines of this file in the same piece of work. Keep entries to a few lines. No history, no plans: only what exists.

A local Windows app that turns one picture into a rigged, game-ready 3D model in six steps. Nothing is uploaded; no model is bundled. Not repeated here: [README.md](README.md) (install and use), [docs/FIRST-TIME-SETUP.md](docs/FIRST-TIME-SETUP.md), [docs/ADVANCED.md](docs/ADVANCED.md) (settings, running from source), [docs/API.md](docs/API.md), [docs/BACKEND.md](docs/BACKEND.md) (module map, adding an engine), [docs/BUILD-THE-EXE.md](docs/BUILD-THE-EXE.md).

## 2. Data model (`db.py`, `library.py`)

- **Project**: name, platform, `style_lock` (the look), optional `unity_project_path`.
- **Asset**: category, look (`style_preset`), platform, prompt; `base_asset_id` (variant), `autopilot` state, `held_item`/`equipment` (items), `hair` (library choice), `face_matters`, `wears_armour`/`body_is_metal` (the two step 1 tick boxes; NULL = read the description, a tick wins; the clean-up reads them).
- **Version**: one result of one step: `stage`, `parent_version_id`, `status` (`queued`, `running`, `done`, `error`, `rejected`; "stopped" = rejected with error `cancelled`), `params`, `files` (key to library-relative path), `metrics` (including `checks`), `selected` (kept; one per asset and stage).
- **Job**: the queue row: `instance` (`a`, `b`, `host`), `kind` (`<stage>.<op>` or `material.<stage>.<op>`; ops `run refine adjust upload upscale compose judge`), `status`, `progress`, `message`, `payload`.
- A run's parent is the kept version of the previous step (`pipeline.run_stage`; the material category skips step 2). A **redo** is a sibling with the same parent. **Refine** (a change in words) and **adjust** (settings) make a child version of the same step with the parent's params as the start (`reference.inherited_params`: a concept's `prompt_override` is not carried on, so the description is read again). Nothing is overwritten. Steps find inputs by walking up the parents, then the kept version of each step (`StageContext.lineage_file`).
- Files: `library/projects/<project>/assets/<asset>/<stage>/<version>/`, served by `GET /api/library/{path}`. Exports are also copied to `exports/<project>/<asset>/` beside `library/`, which also holds `vgac.sqlite`, `prefs.json`, `engines.json` and the registries of the person's own parts.
- Schema changes: add a nullable column to `_ADDED_COLUMNS` in `db.py`; there is no other migration.

## 3. The six steps

Each is `backend/vgac/stages/<stage>.py` with `run`, `refine`, `adjust`, `judge`; `stages/base.py` gives it a `StageContext`; its `register` and `set_metrics` re-read the stored file list and metrics first, so keys another job adds to the same version survive. Settings: `reference.STAGE_SCHEMAS`. Checks go in `metrics.checks`.

The **material** category (tileable surface) uses `stages/material.py` for steps 1, 3 and 6 on card B and skips 2, 4 and 5. A realistic wood material at a 2048 texture (WP-58, `graphs/material.py` `upscale_plan`) is drawn at 1024 and, after the seamless blend, wrap-padded, upscaled 4x by the optional `4x-PBRify_UpscalerV4.pth` and resized to 2048 (`stages/material.py` `_upscale_wood`); the 1024 draw happens only when the card lists that model (`concept_draw_size`), and an upload or a picture of another size keeps today's tile.

**Clean-up order** (`stages/prep.py` `_prep`):
1. facing decision, outline test then a toes test as tie-break (`facing.py`); for buildings (`facing_by_picture` in the category file) the square-on step 1 picture against the mesh audit's renders at the four quarter turns sets the turn first when it clearly picks one pair of opposite sides (`facing.by_picture`; odd angles and other pictures are refused), and for a square footprint, where the outline cannot tell the sides apart, by colour alone with a wider margin (`facing.square_footprint`, `SQUARE_DE`; validated on one real square build only, and the outline overlap condition is required there, since one wrong picture reached a colour margin of 8.83); a near-tie with no toes, or a flat model (`facing.FLAT_DEPTH`, no toes read), keeps the side the 3D step built as the front unless the colour of the drawn front and back views against the mesh audit's renders clearly says the other side (`facing.colour_evidence`); when nothing settles it, `facing_tests` warns with a turn-round fix and autopilot stops to ask; its sentence names the turn applied and what settled it (outline, toes, colours, or the person's choice)
2. normal-map repair for old 3D versions (`normalfix.py`)
3. Blender `prep.py`: turn, size, pivot, weld, weighted decimation to the budget, shading, optional symmetrize, hole fill (new faces with an edge stretched across the texture are given corners beside a neighbour: `blender/fillmend.py`; report `fill_faces`, `fill_mended`, `fill_unmended`), grid snap for scenery, rebake (cage 0.01 x the model's diagonal, half that for humanoids: `blender/rebake_cage.py`)
4. texture pass: measure, physically based fix, look applied; light removed here only when no picture will be painted; a look with a bake size (recipe `mesh.bake_texture`, Retro 64) is not shrunk here. For a look with `surface.face_layout` (Retro 64) the face then gets more of the texture (`face_detail.layout_only`, `blender/faceuv.py`), with no face paint pass
5. picture projection into the base colour (`srcproject.py`). The head is painted first by a chain of head views: the front picture fitted on the head by eyes and mouth (`facemarks.use_local`, MediaPipe on the processor), then each three-quarter view fitted the same way and lined up to what the front painted (refused when over 0.12 of the face width away); each three-quarter head picture takes the front's skin tone by one offset measured where the two overlap. Where a three-quarter head picture's own ear lands 1 cm or more from the model's (MediaPipe pose ear points), the picture round its ear is moved onto the model's ear, fading to no movement before its eyes and mouth; only where skin of the head's own tone shows round both ear points (not under hair). Whole-body fits do not paint where a head view paints; they hand over gradually down about 6 cm of neck, their tone matched to the head views' in that band. A head view never paints its frame margin or surface seen beyond about 70 degrees; the chin underside takes the painted colour around it. A whole-body view does not paint within `OVERLAP_PX` (24) pixels of a depth step over `OVERLAP_JUMP_M` (3 cm), where one body part sits in front of another; those texels come from a view that sees them clear, or keep the 3D step's colour. Small unpainted holes enclosed by paint (up to about 2 cm across) take the mean colour of the painted surface round them; larger unpainted areas keep the 3D step's colour. Left, right and back views never paint the face; a view whose turn contradicts the front is refused; with the facing decided (or chosen), the original picture and the built-from picture are fitted only within `FRONT_HALF` (100 degrees) of the front; between turns whose outlines fit alike, the head's own match decides (weight 20). Unpainted skin inside the eyes-nose-mouth box takes the painted skin tone. The version's `quarter_pictures` (default on) false leaves the two three-quarter pictures out of this pass and of the face pass's side views (`srcproject.without_quarters`). Where a later whole-body view meets the views before it, a smooth tone field fitted on their overlap and fading to nothing a few centimetres from the join levels its colour to theirs (`srcproject.tone_adjust`, `JOIN_BLEND`); head views and the first whole-body view are not adjusted, and a global per-view tone match was tried and rejected (WP-50 trial B).
6. skin never metal (`skinmetal.py`): head, neck and the rest of the bare skin; armour in the description limits it to head and neck; creatures (quadruped, winged, multileg, serpent) are not metal unless the description says so (`creaturemetal.py`, after the texture passes): metal-look or armour words keep the builder's metal (gold, silver, copper, bronze and brass only when not describing fur, hair, feathers, scales or a breed), shine words clear metal and cap roughness at 0.35
7. hair found (`stages/hair_detail.py`); a grey metal crown is a helmet only when light enough to be steel and the face skin was not marked metal
8. face detail: close-up, fit, paint; a close-up is used only above its likeness bar, 0.85 for the painted look (`LIKENESS_MIN_PAINTED`), 0.93 for cartoon and the other looks, 0.90 for photographic looks, 0.88 for guided close-ups (`likeness_bar`, recorded with each close-up); the eyes and mouth come from the darkest-spot finder first, with MediaPipe (card, or the processor) only where it finds no eye or mouth band, the close-up recording which finder read them (`landmark_finder`); held back when the fit scores under 0.65 (`stages/face_detail.py`, `face.py`, `facecloseup.py`, `facemarks.py`); in the picture's eye boxes the colour-only hair mask is cleared unless a depth step marks a real flap in front of the eye (`release_eye_hair`), and the freed eye boxes are painted again without the 3D softening; skin never metal runs again when it laid the texture out anew
9. hair detail painted, optional own hair material (`hair.py`, `hairmat.py`)
10. light removed after painting (`lightfix.py`): Realistic look with pictures painted, only where same-coloured texels show a light gradient, at most one stop; `base_color_lit.png` keeps the original. Then, by look: one colour per triangle (`surface.colour_per_face`, Low-poly, `looktex.py`; the front of a character's head kept as painted (`looktex.front_of_head` with `whole_front`: the face finder's region together with the geometric front of the head, which ends at the neck, `NECK_NARROW`; the Retro 64 face layout keeps the finder's region alone); in every category a triangle also keeps its painted texels when at least 10% of its interior texels lie more than 10 Lab from its median (`looktex.detailed_triangles`, so a window or lettering inside one triangle survives); the test looks at colour spread only: it has no flat-region or sharp-edge condition, so noise in the step 3 texture is kept as detail too, and a plane-fit or neighbour-normal flat-region test keeps almost nothing on the jittery generated meshes)), and a look with a bake size shrunk to its shipped size, each texel from its own texture piece (`prep.ship_late`, `imaging.shrink_by_island`); the normal map ships at the base colour's size, shrunk per texture piece and renormalised (`imaging.shrink_normal_islands`, in `prep.texture_pass` and `apply_look`); when a look ships smaller than it was painted, every map is shrunk per texture piece (`imaging.shrink_by_island` / `shrink_map_islands` / `shrink_normal_islands`) and grown into the empty space, with the box filter only when there is no UV layout
11. physically based figures measured again on the finished maps
12. library hairstyle fitted to the body (`hairfit.attach`)
13. checks computed, incl. `picture_projection`, `skin_not_metal`, `facing_tests`, `face_finder`, `baked_light`; a texture check that cannot be measured says so (`quality.not_measured`)

Face and hair passes skip (reason recorded) for non-humanoids, flat looks, when off, or when nothing is found.

## 4. Job queue (`jobs.py`)

- One asyncio worker per ComfyUI instance in `config.yaml` plus one for the host; one job at a time each. Every worker waits while free RAM is under `min_free_ram_gb`.
- **Routing** (`route()`): the person's default card if it can run the work; else the step's card from `stage_instances` (`material_stage_instances`, `judge_instance`); else the first card that is on, allowed that kind (`allowed_kinds`) and capable (`instance_capabilities`; rigging is `b` only); else the job waits with a message. Host steps always run on the host.
- **Card off**: queued jobs move, the running job is stopped and requeued, never cancelled.
- **Share when busy**: an idle card takes the oldest waiting job from a busy card; a job is never split and a running job never moves.
- **Borrowing**: a running step may `lend` another card for part of its work (step 2; the host's clean-up for its face close-up, naming the work `kind` and the card to `avoid`). Lent only if on, allowed, idle, nothing waiting, engine already answering, enough free memory (`LEND_MIN_ROOM_GB`); the host borrows nothing while a step 2 job waits. Handed back at end, failure or stop; turning it off revokes it. An idle engine short of memory is told to let go of its models and is measured again. The face pass holds the card of its first close-up as a lease.
- **Engine address**: an engine's port is never looked up again while it has a job (`instances.py`, `comfy.py`).
- **ComfyUI input copies**: `ComfyClient.stage_input` copies each "vgac_" input into ComfyUI's input folder and records its name and time in `comfy_inputs_staged.json` in this backend's library folder. `comfy_inputs.sweep` removes only files in that record (older than 6 h, no active job id in the name); files this backend did not stage, and other backends' files, are never touched (`comfy_inputs.py`).
- **Host lanes**: clean-ups run on the host's main worker, first come first served; exports run on a second worker (`HOST_QUICK`), so they do not wait behind another asset's clean-up, and one asset never has two host jobs at once. `host_cleanup_workers` (default 1) raises the number of clean-up workers.
- **Cards used on the record** (`cardlog.py`, `Job.result`): a job's `cards` list has every card it drew on: `planned` (the card it was queued on, shown before it starts), `own` (the card it runs on, host for clean-up and export, from start to end), `lent` (a loan, with the step that asked, e.g. face redraw or turnaround side) and `drew` (the first face close-up's card, held not lent). `moved` lists each move between cards (sharing, the default card, a card turned off, back in the queue after a stop) with the card it came from. The job log shows the cards in plain words (`frontend/src/cardUse.ts`). `Job.instance` is still the queued card; `result.lent` still lists loans only.
- **Estimates with a second card**: the queue records on the borrowing job how long it had a lent card (`Job.result.lent`); `estimates.split_estimates` keeps runs with and without one apart, and `/api/stages` gives `estimate_two_cards`, `estimate_one_card` and `estimate_note`.
- **Rig first**: a card's queue starts a queued rig job ahead of other assets' long jobs (`jobs._card_pick`), never ahead of its own asset's unfinished earlier jobs, at most two rigs ahead of one waiting job.
- **Keep models loaded**: `instances.cache_ram_args` adds `--cache-ram <active> <inactive>` to engines the app starts when the card's `keep_models_loaded` pref is on (default on); inactive is 15 percent of the PC's RAM, between 6 GB and the free-RAM floor. ComfyUI otherwise drops cached models after any graph that does not use them. A job held for free RAM makes idle engines give their cached models back (`JobQueue.release_cached_ram`). The lending guard does not depend on it.
- **Estimates**: the upper-quarter mark of recent runs; a clean-up's progress follows the clock and the time left only falls; `note_waits` writes what a queued job waits for.
- **Stop** kills the task and child processes and withdraws only the job's own ComfyUI prompts (`comfy.py` `ComfyClient.withdraw`: interrupt only while that prompt runs, delete it while pending; the job's prompts are recorded in `JOB_PROMPTS`); a blind `POST /interrupt` is never sent, because it stops whatever runs on the card; the version becomes "stopped"; **Resume** requeues with the same settings and seeds. A stopped or failed version is not kept (`jobs.py` clears `selected`); Resume keeps it again when its step has no kept version. Delete (`main.py`) removes a stopped or failed version even if it still carries the flag; a finished kept version stays (409). Delete removes that one version only: files a later version links into are copied into it with its paths rewritten (`_take_over_files`), its parent becomes the deleted version's parent, and the delete is refused (409) while a dependent version is queued or running. **Timeout** (`job_timeout_seconds` 3600, `blender_timeout_seconds` 1800) is an ordinary failure. A background cut-out (BiRefNet graph) that gets no result within 300 s of leaving ComfyUI's pending queue is a stalled prompt (`comfy.py` `time_limit_for`, `ComfyStalled`): the step fails with a plain message naming the card and saying to restart its ComfyUI by hand (`jobs.py` `stalled_message`); the app never restarts ComfyUI itself. **Engine lost** mid-job: requeued once, then fails. **Backend restart**: running jobs return to queued.
- Websocket events: `job`, `version`, `gpus`, `autopilot` (`events.py`).

## 7. Conventions

- Anything the person reads is plain language, no stage ids or model file names as labels, no emoji. Wording lives in `guidance.py` (`tests/test_ui_plain_names.py` and `tests/test_option_help.py` enforce it).
- One source per fact (the table in section 5); do not copy it.
- A pass that is skipped records its reason in metrics and says it in plain words; it does not fail the step.
- Warning-only checks for things once measured but not judged (WP-86 part 1, WP-92): `painted_share` (picture painting painted little), `uv_transfer_offset` (`rig_restore.uvs.max_face_offset`), `unreached_texels` (`blender/rebake.py` `measure_unreached`: two one-sample CPU bakes, the target's own coverage and the source's hits; the share is a property of the two surfaces, so one value covers every map; `metrics.rebake_unreached`) and, from `meshchecks.py` on the finished clean-up GLB (`metrics.mesh_measures`), `slivers` (triangles with a corner under 5 degrees; `degenerate_faces` is unchanged), `texel_density_spread` (p95 over p5 of the UV pieces' density) and `flipped_shells` (inside-out closed shells, shells part-turned-over, open shells facing the model's middle). All `look` or `advice`, limits in `quality.py` with their measured basis; wide while the library holds only humanoid and a few prop samples.
- Time log (WP-91): every run of a step records `metrics.timing` = `{part: seconds, ..., total}` (`steptime.py`; wall time, parts added as they finish, `total` written by the dispatcher in `stages/__init__.py`; a timing error is logged and ignored, never fails a job). Parts: step 2 `draw_<view>`, `redraw_<view>`, `draw_sheet`, `pose_ready`, `body_marks`, `bald`; step 3 `graph`, `after_graph` (head build: `head_graph`, `head_after_graph`), `audit`; step 4 `blender_prep`, `rebake`, `texture_pass`, `projection`, `pose_search`, `face_detail`, `sharpening`, `second_compose`, `face_rebake`, `hair_detail`, `judge`; step 5 `skintoken`, `rig_fix`, one part per weights pass, `inspect`, `hitboxes`, `animate`, `skin_stretch`, `judge`; step 6 `pack`, `equip`, `unity`, `sprites`, `beauty`, `judge`, `deliver`. Parts that wait on a card or Blender include the wait; `pose_search` is summed over views and sits inside `projection`, `sharpening`, `second_compose` and `face_rebake` inside `face_detail`, `rebake` inside `blender_prep`. Read it with `backend/tools/timing_report.py` (library DB opened `mode=ro`; median and upper quartile per step and part, filters for dates, category, card and test projects).
- Code with tests but not yet seen on a graphics card is marked `UNTESTED ON A CARD` in the comment and commit message, with a per-version switch (see `stages/turnaround.py`).
- Tests: from `backend/`, `.venv\Scripts\python -m pytest -q tests` (temporary library, no ComfyUI needed; a few need Blender, found by `tests/machine_tools.py`). Launcher: `node desktop/appbridge.test.js`, `node desktop/machine.test.js`. Frontend: `npm run build`, `npm run lint`.
- Loading a change: frontend, `npm run build` in `frontend/` and reload; backend, restart the process (reopening the app does not restart a backend the launcher did not start; check the queue is empty first); launcher, `npm run dist` in `desktop/` with all VGAC processes closed. Ship frontend and backend together.
- No one-size-fits-all: asset types need not share one model or process. A change with a clear benefit for one category (or one subject type, such as realistic people against stylised characters) ships for that category only, through its step defaults (`step_defaults.py`) and category route (`data/categories/*.yaml`, `reference.recipe()`). Trials are judged per category; the others keep their route.
