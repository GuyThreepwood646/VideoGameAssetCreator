# VGAC UI review: findings ranked by severity, with fixes

Date: 2026-11-12. Review only: no code was changed. This report is the input for a later implementation session.

Updated 2026-11-12 (later): merged with the options review in [UX-OPTIONS-REVIEW.md](UX-OPTIONS-REVIEW.md) and its commit a7001e1. See "Merged with the options review" below the summary. That document stays the record for the option-by-option changes; this one tracks every open UI item.

## How this was done

- **Live walkthrough** in the in-app browser against `npm run dev:mock` (demo data) at 1440 x 900 and 1280 x 720. Screens covered: first-run guide, Projects, New project dialog, Look and settings drawer (including Advanced), Project page and New asset form (description mode, picture mode, every category switch), asset steps 0.5 and 1 to 6 on a failed asset (Treasure chest) and a finished one (Knight), a new asset created with Autopilot from start to finish (running, paused on checks, Fix and continue, finished), Make a variant, Add an item, Details (job log), Hair, Change something / Fine-tune, Gallery, Glossary, Credits and Health.
- **Code trace** for states the demo cannot show: backend down, not-found, confirms, live regions, notifications.
- **Visual-system audit** of `frontend/src/styles.css` and inline styles: tokens, contrast, type scale, focus and motion. Contrast ratios were computed from the token hex values (WCAG 2.x formula).
- **Evidence labels:**
  - **Seen**: observed live in the demo.
  - **Code**: verified in source.
  - **Mock?**: may come from demo data rather than the real backend. Check it on the real app before fixing.
- **Not covered:**
  - the real backend and real assets (the demo uses placeholder models and pictures)
  - a screen-reader pass
  - Windows high-contrast mode
  - 200% zoom
  - the Electron launcher's status window (`desktop/status.html`)
  - the Setup check badge in a real install (it does not render in demo mode)

**Severity scale:**
- **Critical**: misleads the person into a wrong action, or blocks the core job.
- **High**: a frequent source of confusion or friction on the main path, or an accessibility failure.
- **Medium**: friction or inconsistency that costs time or trust.
- **Low**: polish.

IDs use `UI-`. Each finding has three parts: what is wrong, where it is, and the fix.

The purpose this review measures against is the README promise: "Type one sentence. Get a textured, rigged, animated 3D character or prop, ready for your game". The person is a game maker who is not a 3D artist. They should always know what is happening, what to do next, and how to get the result into their engine.

**The five themes that matter most:**

1. **One vocabulary.** "Look", "style preset", "style lock" and "recipe" are four words for one idea, and they come with two different lists of styles. Internal names leak into the plain layer: `pc mid`, `prep`, `texture voxel`, `readiness_block`, `Instance b`, `v0401-mo`, `tris`.
2. **One next action.**
   - The next-step card can contradict the real state.
   - Several screens show two or three primary-looking buttons, or three Stop buttons.
   - The "Happy with this?" decision sits below the fold.
3. **The finishing moment does not deliver.** "Your asset is ready" leads with "Make another". The files are 11 equal grey buttons. Sending the asset to Unity is hidden behind a collapsed section.
4. **The numbers disagree with each other.**
   - Check counts differ between the finished bar and the step.
   - Three triangle counts appear on one screen.
   - Three different move lists appear on one step.
   - The GPU memory figure is reported two ways.
5. **The visual system has drifted.**
   - There are 14 font sizes and 6 unnamed greys.
   - Red text fails contrast.
   - Input and button edges fall below 3:1.
   - Buttons and links have no single focus ring.
   - One rail item renders its label invisibly.

**What to protect (works well today):**
- The plain step names.
- The "Happy with this? Keep / Try again / Change something" framing.
- The quality-check sentences that come with fix buttons, such as "Shrink to the budget" and "Close the holes".
- Autopilot's pause card listing exactly what failed.
- The welcome guide.
- The "i" help on every term.
- The finished bar on steps 1 to 5 (STEP-FOCUS spec).
- The look presets as cards.
- Smart detection in the prompt, which offers library hair and separate items such as the backpack.
- "Your pictures stay on this computer".
- From a7001e1: the dependent greyed states in Fine-tune, each with its reason ("Turn on Pose for 3D first to use this."), and the step 2 row that shows the step 1 picture beside the "Redrawn for 3D" picture.

### Conflict decided by the owner (2026-11-12)

1. **Raw parameter names in Fine-tune.** UI-08 says to keep internal names out of the plain layer. Every Fine-tune setting already shows its parameter name in grey monospace after the hint (`FineTune.tsx` line 537), and a7001e1's new Automatic / On / Off selects follow the same pattern (`(source_project)`, line 361). a7001e1 is consistent with the existing code, so this is not a mistake in it, but it does add two more places that UI-08 would change.    **Decided (owner, relayed by the options review session):** "the technical names are good to keep, but shouldn't be the main focus." The rule for every field: the technical name stays visible but secondary. The plain label and the hint lead; the name follows small and muted (as the grey monospace after the Fine-tune hints does today), and is never the label or the only text. a7001e1's selects already follow this rule, so they need no change. UI-08 below is updated to match.

Not conflicts, but worth knowing:
- a7001e1 uses a native select for Automatic / On / Off. UI-35 recommends one segmented control for small fixed choices. Converting it later is a restyle, not a reversal.
- a7001e1 dims a disabled setting's label to 60% opacity. The label colour (`--muted`, 11 px) then measures about 3.0:1 on the panel. Disabled controls are exempt from the WCAG text contrast rule, so this passes, but the reason text under it must stay at full strength, as it does today.

## Critical

### UI-01. Two different style lists, and three names for the same idea
**Status:** Done (9ad9725, 9bbe463). One list of looks everywhere: the asset form defaults to the project's look with a disclosure for a different one, cards, header, gallery and help use look names, and a model name is never shown as a look. The data is now merged by owner decision: each style in `styles.yaml` is also a look (`look_label`, description, example prompt and a `lock` with the painting settings), `style_presets.yaml` is gone, and `/api/style-presets` is built from the merged data. The look id is the old style id (painted, cel, pixel, retro64, lowpoly_flat, realistic_pbr, clay), so every pipeline reader behaves exactly as before; the five old look ids (painted_fantasy, clean_cartoon, pixel_retro, realistic, clay_toy) map to them in `db.migrate_looks`, which also moves assets with an unknown style to the project's look, is idempotent, and copies the database to `<db>.before-looks-merge` first. Retro 64 and Low-poly flat are now looks, with the sample pictures. A custom look (no preset) carries `based_on`, shown as "Based on: ..." in the drawer and on the project card. Tests: `test_looks_merge.py` (every look has both parts, every old id maps, migration and backup).
**Where (Seen):**

| Place | What it shows |
|---|---|
| New project dialog and Look and settings drawer | "Looks": Painted fantasy, Clean cartoon, Anime cel, Pixel retro, Realistic |
| New asset form, "Style preset (look)" | A different list: Hand-painted stylised, Realistic PBR, Pixel art, Toon shaded, Cel shaded (anime), Retro 64, Low-poly flat |
| Gallery cards | Tagged with the second list ("Hand-painted stylised") |
| Project header | "PC and console / Painted fantasy / style lock" |
| Glossary | Defines "Style lock" |
| New asset form, extra line | "Recipe: Hand-painted character" |
| Projects page, Scrapyard Racers card | Subtitle is the model name ("FLUX.2 Klein 4B / Phone") instead of a look name |

**Why it matters:** the person picks "Painted fantasy" for the project, then meets a dropdown that never mentions it except in brackets. They cannot tell whether a "style preset" overrides the project look or adds to it. "Recipe" is a third concept they never chose.

**Fix:**
- Use one taxonomy, named "Look", everywhere: the project card, the drawer, the asset form, gallery tags, the project header and the glossary.
- In the asset form, show the project look as the default, written as "Look: Painted fantasy (this project's look)", with a "Use a different look for this asset" disclosure that lists the same five looks.
- Fold the "style preset" and "recipe" into what a look means internally, and show them only in Advanced.
- Retire "style lock" from the UI. Keep it as the technical name in the glossary.
- Never show a model name as a look name.

### UI-02. The next-step card can contradict a failed step
**Status:** Done (4e83cd0). A failed later step now outranks Make it: the card says which step did not finish, with Try again on that step (when it is the next one) and Go to it.
**Where (Seen):** Treasure chest, step 1 page. Step 2 has failed: there is a red dot in the rail and "Check all sides: The generator stopped..." in the status line. Yet the next-step card says "You kept version 1. 'Check all sides' already has 1 result. Continue there." The primary button is "Make it, about 9 minutes".

**Why it matters:** the one card that exists to say what to do next tells the person to "continue" into a failure, and offers a 9-minute Autopilot run as the main action.

**Fix:**
- The guide state for any step page must first check for the earliest failed or "needs a look" step after the current one.
- When it finds one, the card says "Step 2, Check all sides, did not finish." with a primary "Try again on step 2" (it can run from this page) and a secondary "Go to step 2".
- "Make it" is not the primary action while a failure is unresolved.

### UI-03. The finish screen does not lead with delivery
**Status:** Done (25ee298, 729ac0f). Corrected after checking the export code: export already copies into the project's Unity path by itself, and the Unity hand-off only re-judges. The card therefore says "Copied to your Unity project" with the path and an Open the Unity folder button when a Unity project is set; otherwise Open the asset folder is primary with a quiet Set a Unity project link to Look and settings. Download FBX, Download everything (.zip), the grouped All files list and the quiet What next row are in. Re-sending is just running step 6 again; no new API. The viewer already asks for the Walk clip; the demo model has none, so autoplay was not seen.
**Where (Seen):** step 6 finishing card ("Your asset is ready").

- **Files are a flat row of 11 identical grey buttons:** "FBX (most engines)", "GLB (web, Blender)", "manifest", "colour texture", "bump texture", "metal and shine texture (Unity)", "surface texture (Unreal, Godot, web)", "sprite atlas", "sprite sheet". None shows a size or format. There is no "Download all" and no "Open folder".

**Why it matters:** this is the moment the product promised. The person should leave with the asset in their game in one click.

  1. Primary: "Send to Unity" when a Unity project is set, otherwise "Open the asset folder" (Electron `shell.openPath` on the export folder).
  2. Secondary: "Download FBX".
  3. Secondary: "Download everything (.zip)".
- Put the per-file list under "All files (11)". Group it into Model (FBX, GLB), Textures and 2D (sprite sheet, atlas). Show size and purpose per row, and move "manifest" into a "Technical" sub-group.
- Autoplay the first move (Walk) in the hero viewer for rigged assets, with Turntable as a toggle.
- Move "Make another" and "Make a variant" to a quieter "What next?" row.

### UI-04. Asset names are cut from the prompt mid-phrase and cannot be set
**Status:** Done (eb99dfc, 011e788). Names are cut at the first preposition or comma, a Name field is visible on the form, and the rail title can be renamed in place. The exports folder takes the new name on the next export, because the delivery folder is built from the current asset name.

- "Items on Grumpy goblin merchant with"
- "Grumpy goblin merchant with went through all 6 steps."
- the variant default name "Grumpy goblin merchant with - ...", which also becomes the exports folder name

**Fix:**

- Write sentences that include the name defensively: "Your Grumpy goblin merchant went through all 6 steps", or put the name in a heading instead of mid-sentence.

### UI-10. Red text and control edges fail contrast; there is no consistent focus ring
**Status:** Done (aa43d52). --bad raised, --border-control added for controls (3:1), one focus ring for all controls, and a 12 px floor through the type tokens. Ratios come from the token values, not re-measured in the browser; high-contrast mode not checked.
